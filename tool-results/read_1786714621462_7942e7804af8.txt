  1133→# 28. Anti-Duplicate Answer Handling
  1134→
  1135→Important for real-time activities.
  1136→
  1137→A participant should only be able to answer once per question.
  1138→
  1139→Database constraint:
  1140→
  1141→```text
  1142→UNIQUE(
  1143→    participant_id,
  1144→    question_id
  1145→)
  1146→```
  1147→
  1148→If they click twice:
  1149→
  1150→```text
  1151→First request → accepted
  1152→Second request → rejected/ignored
  1153→```
  1154→
  1155→This should also protect against network retries.

  1159→# 29. Timer Architecture
  1160→
  1161→Do **not** rely on JavaScript's local countdown as the actual timer.
  1162→
  1163→Server stores:
  1164→
  1165→```text
  1166→question_started_at
  1167→question_ends_at
  1168→```
  1169→
  1170→Example:
  1171→
  1172→```text
  1173→question_started_at = 19:30:00
  1174→question_ends_at    = 19:30:30
  1175→```
  1176→
  1177→The client calculates the visual countdown from server timestamps.
  1178→
  1179→Therefore:
  1180→
  1181→```text
  1182→Admin computer clock
  1183→        ≠
  1184→Participant computer clock
  1185→```
  1186→
  1187→doesn't matter.
  1188→
  1189→The server determines the actual deadline.

  1751→# 43. Most Important Product Principle
  1752→
  1753→Don't build this as:
  1754→
  1755→> "An online MCQ management system."
  1756→
  1757→Build it as:
  1758→
  1759→> **"A live presentation system where each question is a slide."**
  1760→
  1761→That distinction should drive the entire UI.
  1762→
  1763→The admin should think:
  1764→
  1765→```text
  1766→Slide 1 → Slide 2 → Slide 3 → Results → Slide 4
  1767→```
  1768→
  1769→rather than:
  1770→
  1771→```text
  1772→Question database → Question record → Answer record
  1773→```
  1774→
  1775→Internally it is still a database-driven quiz system, but **the user experience should be presentation-first**.
