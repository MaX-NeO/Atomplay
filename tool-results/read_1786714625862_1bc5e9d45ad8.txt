     1→     1→Absolutely. For your requirement, I would keep the **MVP much smaller than Mentimeter**, but follow its core interaction pattern:
     2→     2→

     7→     7→# Product Requirements Document — Real-Time Quiz Activity Platform
     8→     8→

    11→    11→**MVP focus:** MCQ activities only
    12→    12→**Authentication:** Admin only
    13→    13→**Participant authentication:** None
    14→    14→**Primary interaction:** Access-code based joining

    19→    19→## 1. Product Vision
    20→    20→
    21→    21→Build a lightweight real-time quiz platform that allows an administrator to create interactive MCQ activities and conduct them live with participants.

    24→    24→

   763→   763→
   764→   764→Is activity live?

   768→   768→
   769→   769→Then:
   770→   770→
   771→   771→Save answer

   898→   898→# 21. Activity State Machine
   899→   899→
   900→   900→Use an explicit state machine.
   901→   901→
   902→   902→```text
   903→   903→                 ┌─────────┐
   904→   904→                 │  DRAFT  │
   905→   905→                 └────┬────┘
   906→   906→                      │
   907→   907→                   Publish
   908→   908→                      │
   909→   909→                      ▼
   910→   910→               ┌─────────────┐
   911→   911→               │  PUBLISHED  │
   912→   912→               └──────┬──────┘
   913→   913→                      │
   914→   914→                    Start
   915→   915→                      │
   916→   916→                      ▼
   917→   917→                 ┌─────────┐
   918→   918→                 │  LIVE   │
   919→   919→                 └────┬────┘
   920→   920→                      │
   921→   921→                     End
   922→   922→                      │
   923→   923→                      ▼
   924→   924→                ┌───────────┐
   925→   925→                │ COMPLETED │
   926→   926→                └───────────┘
   927→   927→```
   928→   928→
   929→   929→This prevents invalid operations.
   930→   930→
   931→   931→For example:
   932→   932→
   933→   933→```text

   935→   935→```
   936→   936→
   937→   937→should not be allowed.
   938→   938→
   939→   939→It must first be:
   940→   940→
   941→   941→```text
   942→   942→DRAFT → PUBLISHED → LIVE
   943→   943→```

  1134→  1134→
  1135→  1135→Important for real-time activities.
  1136→  1136→
  1137→  1137→A participant should only be able to answer once per question.
  1138→  1138→
  1139→  1139→Database constraint:
  1140→  1140→
  1141→  1141→```text

  1143→  1143→    participant_id,
  1144→  1144→    question_id
  1145→  1145→)
  1146→  1146→```
  1147→  1147→
  1148→  1148→If they click twice:
  1149→  1149→
  1150→  1150→```text
  1151→  1151→First request → accepted
  1152→  1152→Second request → rejected/ignored
  1153→  1153→```
  1154→  1154→

  1159→  1159→# 29. Timer Architecture
  1160→  1160→
  1161→  1161→Do **not** rely on JavaScript's local countdown as the actual timer.
  1162→  1162→
  1163→  1163→Server stores:
  1164→  1164→
  1165→  1165→```text
  1166→  1166→question_started_at
  1167→  1167→question_ends_at
  1168→  1168→```
  1169→  1169→
  1170→  1170→Example:
  1171→  1171→
  1172→  1172→```text
  1173→  1173→question_started_at = 19:30:00
  1174→  1174→question_ends_at    = 19:30:30
  1175→  1175→```
  1176→  1176→
  1177→  1177→The client calculates the visual countdown from server timestamps.
  1178→  1178→
  1179→  1179→Therefore:
  1180→  1180→
  1181→  1181→```text
  1182→  1182→Admin computer clock
  1183→  1183→        ≠
  1184→  1184→Participant computer clock
  1185→  1185→```
  1186→  1186→
  1187→  1187→doesn't matter.
  1188→  1188→
  1189→  1189→The server determines the actual deadline.
